# Migration decisions and limitations

* Java 21, Quarkus CLI and parameterized JDBC replace the COBOL orchestration and DB2 cursor, without an HTTP service. The original programs, DDL, JCL and historical fixture evidence are retained.
* Correctness takes precedence over defect parity: the first selected operation is included, account and branch are explicit, the supplied date is the cutoff, dates retain their complete value, and decimal fractions and totals are not silently discarded. See the traceability matrix for source references. The existing JCL does not provide an account; an operator or upstream integration must provide it.
* Report and log labels are English. Identifiers and data are not translated. Consequently even equivalent records cannot be expected to match the Portuguese COBOL report byte for byte. Corrected selection, calculations, statuses, logging and failures may create additional intentional differences. Comparison must classify differences against independently approved expectations, not require unconditional byte parity.
* Legacy detail money is left-aligned after trimming and uses a comma editing mask. Java right-aligns numeric values and uses a decimal point; fixed-position consumers must be adapted and approved separately from the English-label change.
* Fixed 132-byte records are not sufficient to establish mainframe compatibility: charset/CCSID, file transfer, DB2 driver behavior, collation, decimal boundaries, locking and error handling require validation in the target environment. Numeric or encoded values that cannot fit must be rejected rather than silently truncated.
* The local mock is a convention, not a replacement for DB2. Its original ten fields omit branch and reference date. `README.md` describes how the Java reader handles these missing values; test DB2 separately.
* The previous golden and the historical differential and homologation scripts are retained as evidence of the old implementation, not acceptance tests for this version. A prior local GnuCOBOL match does not establish IBM COBOL, DB2 or z/OS parity.
* Preserve the COBOL job as the rollback option. Run an isolated parallel qualification with authorized synthetic or anonymized data, compare against independently approved functional expectations, and obtain business and operational approval before changing any scheduler. No JCL or deployment change is performed here.
