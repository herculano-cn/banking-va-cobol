# COBOL to Java traceability

This matrix describes source-level analysis, not production equivalence. Legacy COBOL, JCL, DDL, mock data and golden files remain unchanged. The local mock is not a DB2 or IBM COBOL execution. See [README.md](README.md) for the executable contract and [TRANSLATION_DECISIONS.md](TRANSLATION_DECISIONS.md) for deliberate incompatibilities.

Java implementation anchors are `Main` (CLI and configuration), `Fontes` (mock and DB2 readers), `Extrato` (batch, files and logging), `Formato` (fixed-record layout and validation), and `Operacao` (operation data), under `src/main/java/br/com/air/extrato/`. Tests under `src/test/java/br/com/air/extrato/` exercise local behavior, not DB2/z/OS deployment.

| Area | Legacy evidence | Migration and remaining evidence |
| --- | --- | --- |
| Entry point and operation | `EXTCRDJ.jcl:9-12,25-42`; `PGMEXTRT.cbl:78-83,169-194` | Quarkus CLI replaces the batch entry point; JCL supplies date and branch but no account, and `WS-PARM` is not a LINKAGE parameter. Effective host PARM handling remains unverified. Scheduling, DD allocation and printing are external. |
| Selection | `PGMLECRD.cbl:94-120,188-192`; `PGMEXTRT.cbl:244-246` | DB2 joins `DB2PROD.TB_CLIENTE` and filters account, branch, A/I and reference date, ordering by modality and contract with `WITH UR`. Legacy incorrectly moves the date into the account, derives branch from account and uses current date; Java takes explicit account, branch and cutoff. DB2 collation and uncommitted reads remain deployment concerns. |
| First row | `PGMLECRD.cbl:162-175`; `PGMEXTRT.cbl:203-208,272-280` | The initial legacy call fetches a row that the processing loop does not print or total. Java processes the first selected row. |
| Date | `PGMLECRD.cbl:104,240`; `PGMFMTEXT.cbl:267-275` | Legacy takes the first eight characters of ISO `YYYY-MM-DD` before formatting as `YYYYMMDD`; Java formats the complete date. |
| Amounts and count | `PGMFMTEXT.cbl:31-35,249-259`; `PGMEXTRT.cbl:122-127,342-347`; `TB_CREDITO_DDL.sql:44-47` | Legacy numeric editing loses cents and moves totals and counts to narrower fields. Java uses exact decimal arithmetic and fails when a report field cannot hold a value instead of silently truncating. Detail fields accommodate signed DDL `SMALLINT` and `DECIMAL(13,2)` values; aggregate totals and counts can exceed their report widths. |
| Modality | `PGMLECRD.cbl:81-89,244-254`; `TB_CREDITO_DDL.sql:67-69` | DDL permits `RF` in `CHAR(3)` whereas the legacy lookup contains `RFI`, so the legacy result falls back to `OUTROS`. Java's actual mapping is described in the README. |
| Output and logging | `PGMFMTEXT.cbl:55-145,204-207`; `PGMEXTRT.cbl:334-370`; `EXTCRDJ.jcl:32-42` | Legacy emits a single header, details and footer, and attempts the final log write after closing the log. Java uses fixed-size records and English report/log labels, deliberately incompatible with the Portuguese legacy bytes. Host CCSID and log behavior are not established. |
| Errors | `PGMGRVEXT.cbl:87-97`; `PGMEXTRT.cbl:319-328,372-380` | Legacy writer OPEN failure returns `9` while caller checks `2`; Java treats file errors as fatal. Exact host FILE STATUS, RC and partial-output behavior are not equivalent by assumption. |
| Local input | `PGMLECRD_mock.cbl:23-38`; `scripts/gen-mock-from-dat.awk` | The legacy ten-field mock is compiled into COBOL and does not contain branch or reference date. Java reads a file at runtime and documents its explicit convention for missing selection fields. Local results cannot validate DB2 query execution. |

No IBM COBOL, DB2 or z/OS execution is implied by this matrix. The historical `SAIDA.golden`, differential script and synthetic homologation wrapper target the previous defect-compatible behavior; none validates the corrected report. Any deployment requires independent, approved business reconciliation and operational testing with suitable data, encodings and failure cases.
